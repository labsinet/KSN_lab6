# Інструкція для викладача

## Підготовка шаблону
1. Створіть репозиторій на GitHub, завантажте вміст цього архіву, у **Settings → General** увімкніть **Template repository**.
2. Студенти натискають **Use this template** (або ви використовуєте GitHub Classroom і вказуєте цей репозиторій як шаблон завдання).
3. Якщо репозиторій публічний, **видаліть теку `teacher/`** (там еталонні конфігурації) і workflow `selftest.yml`. Залиште їх у своїй приватній копії.

## Самоперевірка тестів
`python -m pytest teacher` — перевіряє, що еталони для варіантів 1, 3, 9, 10, 18 дають 8/8, а типові помилки (хибна адреса, `shutdown`, немає підінтерфейсу, немає trunk, хибний VLAN порту, непізбережена конфігурація) знімають бали. Той самий набір запускає workflow `selftest`.

## Зміна правил
- Адресація: `tests/plan.py` (формули варіантів). Ваги тестів: маркер `@pytest.mark.points(...)` у `tests/test_*.py`.
- Після будь-якої зміни в `tests/`, `pytest.ini` або workflow виконайте `python teacher/make_checksum.py` і закомітьте `integrity.sha256`.

## Захист від редагування тестів
Перевірка `integrity.sha256` лише стримує випадкові зміни: студент технічно може змінити й workflow. Для суворішого варіанта:
- у GitHub Classroom використовуйте захищені файли (protected files), або
- налаштуйте Rulesets/CODEOWNERS для `tests/**` та `.github/**`, або
- винесіть перевірку в reusable workflow з окремого приватного репозиторію викладача.

## Збір оцінок
Кожен запуск зберігає артефакт `grade` (`grade.json`: варіант, бали, результат кожного тесту). Для виставлення оцінок візьміть артефакт останнього запуску на гілці `main` кожного студентського репозиторію (GitHub CLI: `gh run download`).

## Обмеження перевірки
- Перевіряється лише текст конфігурацій, а не робоча топологія; фактичну зв'язність (`ping`) і `.pkt` можна переглянути вручну або перевіряти вибірково.
- Перевірка очікує порти та інтерфейси з методички (Gig0/0, Gig0/1; Fa0/1–6 на SW2; trunk на Gig0/1). Інші розкладки портів тест позначить як помилку.
- Команда `vlan N` / `name` у Packet Tracer часто не потрапляє в `startup-config`, тому наявність VLAN береться з `SW2_vlan.txt` (`show vlan brief`).
