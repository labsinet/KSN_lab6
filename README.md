# Практична робота №6. Маршрутизація в Cisco Packet Tracer

![autograde](../../actions/workflows/autograde.yml/badge.svg)

Ви виконуєте роботу в Packet Tracer за методичними вказівками, а **текстові конфігурації** пристроїв здаєте в цей репозиторій. Після кожного `git push` автоматично запускається перевірка (вкладка **Actions** → останній запуск → **Summary**).

## Що потрібно здати (папка `submission/`)

| Файл | Що вставити |
|---|---|
| `variant.txt` | лише номер варіанта (1–18), наприклад `7` |
| `R1.txt` | вивід `show startup-config` маршрутизатора з **частини A** |
| `R2.txt` | вивід `show startup-config` маршрутизатора з **частини B** |
| `SW2.txt` | вивід `show startup-config` комутатора SW2 (частина B) |
| `SW2_vlan.txt` | вивід `show vlan brief` комутатора SW2 |
| `*.pkt` | файл проєкту Packet Tracer (наприклад, `Prac6_Прізвище.pkt`) |
| звіт | `report.md` або PDF (перевіряє викладач, автотестами не оцінюється) |

## Як отримати текст конфігурації

1. На пристрої виконайте `copy running-config startup-config` (без цього `startup-config` порожній, і перевірка це покаже).
2. Вимкніть посторінковий вивід: `terminal length 0`.
3. Виконайте `show startup-config`, виділіть увесь вивід у вікні CLI, скопіюйте й вставте у відповідний файл (замість рядків-заглушок).

## Як працює перевірка

Автотести порівнюють вашу конфігурацію з очікуваною для вашого варіанта: IP-адреси шлюзів (`.254/24`), стан інтерфейсів, підінтерфейси `dot1Q`, VLAN, access-порти та trunk. Кожна невдала перевірка показує підказку, що саме виправити.

| Блок | Бали |
|---|:-:|
| Формат і комплектність файлів | 1 |
| Частина A (маршрутизатор R1) | 3 |
| Частина B (маршрутизатор R2 і комутатор SW2) | 4 |
| **Автоматична частина** | **8** |
| Звіт і відповіді на контрольні завдання (викладач) | 2 |

Локальний запуск (необов'язково):

```bash
pip install -r requirements.txt
python -m pytest
```

> Не змінюйте файли в `tests/`, `.github/` та `integrity.sha256`: перевірка цілісності позначить такий запуск як невдалий.
